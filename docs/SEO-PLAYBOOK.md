# SEO, аналітика й конверсії для нового сайту — універсальна інструкція

Документ можна передати розробнику або AI-агенту, щоб з нуля налаштувати SEO, аналітику й відстеження
заявок на будь-якому сайті (Next.js, WordPress, статичний HTML, конструктор). Він не прив'язаний до
конкретного проєкту: спершу зберіть дані з розділу 1, далі пройдіть розділи 2–8 і чек-лист у розділі 9.

---

## 0. Як користуватися (для агента)

> **Завдання:** налаштувати на сайті все з цього документа. Порядок такий:
> 1. Вивчи проєкт: фреймворк, як формуються `<head>`, маршрути, де лежать контент і форми.
> 2. Звір дані з розділу 1. Чого бракує — **не вигадуй**, а постав `TODO` і окремим списком напиши, що запитати в замовника.
> 3. Ідентифікатори (GA4, Ads, Pixel тощо) винось у налаштування або змінні середовища, а не розкидай по шаблонах.
> 4. Кожен тег підключай **рівно один раз**. Перед додаванням перевір, чи його вже немає (у шаблоні, через GTM, через плагін).
> 5. Після налаштування перевір кожен пункт інструментами з розділу 8 і звітуй, що перевірено, а що ні.
> 6. Не вставляй сирі фрагменти коду від Google/Meta, якщо на сайті вже є свій механізм подій. Бери з них лише ID і мітки.

## 1. Що зібрати перед стартом

### 1.1. Дані про бізнес

| Що | Навіщо | Де взяти |
|---|---|---|
| Робочий домен і бажаний варіант (`www` чи без, `https`) | канонічні адреси, sitemap, редиректи | замовник / реєстратор домену |
| Назва бренду, юридична назва | Title, schema.org, футер | замовник |
| Адреса, місто, координати, графік роботи | `LocalBusiness`, Google Business Profile | замовник; координати — Google Maps → правий клік по точці |
| Телефон(и), пошта, месенджери, соцмережі | контакти, `sameAs`, події кліків | замовник |
| Логотип (SVG/PNG ≥ 512×512), фавікон | `logo` у schema.org, іконки | замовник / дизайнер |
| Політика конфіденційності | згода у формах, банер cookies | замовник / юрист |
| Семантичне ядро: запити → сторінки | Title, H1, структура URL | SEO-фахівець; Google Search Console / Ahrefs / Serpstat / Keyword Planner |
| Старий сайт і його URL (якщо є) | карта 301-редиректів | старий `sitemap.xml`, Search Console → «Сторінки» |
| Регіони й мови | `hreflang`, `inLanguage`, `areaServed` | замовник |

### 1.2. Ідентифікатори сервісів

| Сервіс | Формат | Де знайти | Куди підключати |
|---|---|---|---|
| **Google Analytics 4** | `G-XXXXXXXXXX` | analytics.google.com → Адміністратор → Потоки даних → веб-потік → «Ідентифікатор потоку» | `gtag('config', 'G-…')` або тег GA4 у GTM |
| **GA4 Measurement Protocol secret** (за потреби) | рядок | там само → «Секретні ключі API Measurement Protocol» | лише на сервері (`.env`), для подій поза сайтом: боти, CRM |
| **Google Tag Manager** (за потреби) | `GTM-XXXXXXX` | tagmanager.google.com → контейнер | `<head>` + `<noscript>` на початку `<body>` |
| **Google Ads тег** | `AW-XXXXXXXXXX` | Google Ads → Інструменти → Менеджер даних → Тег Google | той самий `gtag`, другий `config` |
| **Мітки конверсій Google Ads** | `AW-…/AbCdEf123` (`send_to`) | Цілі → Конверсії → конверсія → Налаштування тегу → «Установити самостійно» → фрагмент події | подія `conversion` у момент дії (розділ 5.4) |
| **Meta Pixel** | 15–16 цифр | business.facebook.com → Events Manager → Джерела даних → піксель | `fbq('init', …)` після згоди на cookies |
| **Meta: підтвердження домену** | мета-тег або DNS TXT | Business Settings → Безпека бренду → Домени | `<head>` або DNS |
| **Google Search Console** | мета-тег `google-site-verification` або DNS TXT | search.google.com/search-console → Додати ресурс | `<head>` або DNS (розділ 6) |
| **Bing Webmaster Tools** | мета-тег `msvalidate.01` або імпорт із GSC | bing.com/webmasters | найпростіше — імпорт із Search Console |
| **Google Business Profile** | — | business.google.com | NAP (назва, адреса, телефон) на сайті має збігатися з профілем |
| Microsoft Clarity / Hotjar (за бажанням) | ID проєкту | clarity.microsoft.com | лише після згоди на cookies |
| TikTok Pixel, LinkedIn Insight (за потреби) | ID | рекламні кабінети | як Meta Pixel |

## 2. Технічне SEO

### 2.1. Домен, протокол, канонічна адреса
- [ ] HTTPS з валідним сертифікатом (Let's Encrypt / хостинг); HTTP → HTTPS через **301**.
- [ ] Один головний варіант хоста: `www` → без `www` (або навпаки) через **301**.
- [ ] Одна політика щодо слеша в кінці (`/page` чи `/page/`), друга форма — 301.
- [ ] DNS: A/AAAA-записи ведуть **лише** на ваш сервер. Зайвий AAAA (IPv6) на сторонній хостинг ламає сертифікати й частину відвідувачів.
- [ ] `<link rel="canonical" href="https://домен/шлях">` на **кожній** сторінці: абсолютний URL, без UTM і службових параметрів.
- [ ] Сторінки з фільтрами, сортуванням і пагінацією-параметрами мають canonical на основну сторінку (або власні, якщо це окремі посадкові).

### 2.2. URL
- [ ] Людиночитні: латиниця в нижньому регістрі, слова через дефіс. Кирилицю транслітерувати (`/poslugy/bukhhalteriia-dlia-fop`).
- [ ] Без дат і ID у URL сторінок, які довго житимуть (послуги, категорії).
- [ ] Логічна вкладеність: `/poslugy/<послуга>`, `/blog/<стаття>`.
- [ ] **Переїзд зі старого сайту:** таблиця «старий URL → новий URL», редиректи 301 по одному, без масового редиректу всього на головну.

### 2.3. robots.txt
```
User-agent: *
Allow: /
Disallow: /admin
Disallow: /api/

Sitemap: https://домен/sitemap.xml
```
- [ ] Закривати лише службове (адмінка, API, кошик, пошук по сайту).
- [ ] **robots.txt не прибирає сторінку з індексу.** Щоб сторінка не індексувалася, потрібен `<meta name="robots" content="noindex">`, і robots.txt не повинен блокувати її сканування.
- [ ] Тестовий домен (staging) закрити `noindex` або паролем. **Перед запуском обов'язково зняти.** Це найчастіша причина, чому сайт «не індексується».

### 2.4. sitemap.xml
- [ ] Генерується автоматично з реальних сторінок: усі індексовані URL, **без** `noindex`, чернеток, редиректів і 404.
- [ ] Абсолютні канонічні URL, `lastmod` — справжня дата зміни. `priority` і `changefreq` Google ігнорує.
- [ ] Ліміт: 50 000 URL / 50 МБ на файл. Більше — індекс sitemap.
- [ ] Додати в Search Console і Bing (розділ 6).

### 2.5. Статуси відповідей
- [ ] Неіснуюча сторінка → справжній **404** (не 200 з текстом «не знайдено»), з навігацією на головні розділи.
- [ ] Видалене назавжди → 410 або 301 на найближчий аналог.
- [ ] Немає ланцюжків редиректів (A→B→C), лише A→C.

### 2.6. Мова й регіон
- [ ] `<html lang="uk">` (або відповідна мова).
- [ ] Багатомовний сайт: `hreflang` на кожній мовній версії, взаємні посилання, самопосилання і `x-default`.
  ```html
  <link rel="alternate" hreflang="uk" href="https://домен/">
  <link rel="alternate" hreflang="en" href="https://домен/en/">
  <link rel="alternate" hreflang="x-default" href="https://домен/">
  ```

### 2.7. Швидкість і мобільна версія (Core Web Vitals)
| Метрика | Добре |
|---|---|
| LCP (найбільший елемент) | ≤ 2,5 с |
| INP (реакція на дії) | ≤ 200 мс |
| CLS (зсуви макета) | ≤ 0,1 |

- [ ] `<meta name="viewport" content="width=device-width, initial-scale=1">`, без горизонтального скролу на 360 px.
- [ ] Зображення: WebP/AVIF, адаптивні розміри (`srcset`/`sizes`), задані `width`/`height`, `loading="lazy"` для всього, крім головного зображення першого екрана (йому — `fetchpriority="high"`).
- [ ] Шрифти: свій хостинг або `preconnect`, `font-display: swap`, лише потрібні накреслення й підмножини символів.
- [ ] Аналітику й пікселі завантажувати **після** відмальовування першого екрана (async, після події `load` / в idle).
- [ ] Основний контент віддається сервером у HTML (SSR/SSG), а не лише через JS.

## 3. Мета-теги кожної сторінки

| Тег | Правило |
|---|---|
| `<title>` | Унікальний, ~50–60 символів, головний запит ближче до початку, бренд у кінці: `Бухгалтер для ФОП у Харкові — Бренд` |
| `<meta name="description">` | Унікальний, ~120–160 символів, з головним запитом і закликом до дії. Не впливає на позиції, але впливає на клікабельність |
| `<h1>` | Один на сторінку, з головним запитом, не дублює Title дослівно |
| `<h2>`–`<h3>` | Логічна ієрархія без пропусків рівнів, підзаголовки з додатковими запитами |
| `<link rel="canonical">` | Розділ 2.1 |
| `<meta name="robots">` | За замовчуванням не потрібен; `noindex, follow` для службових і дубльованих сторінок |
| `meta keywords` | **Не потрібен**, пошуковики його ігнорують |

### 3.1. Open Graph і Twitter (прев'ю в месенджерах і соцмережах)
```html
<meta property="og:type" content="website">          <!-- article — для статей -->
<meta property="og:site_name" content="Бренд">
<meta property="og:locale" content="uk_UA">
<meta property="og:title" content="…">
<meta property="og:description" content="…">
<meta property="og:url" content="https://домен/шлях">
<meta property="og:image" content="https://домен/og.jpg"> <!-- 1200×630, < 5 МБ, абсолютний URL -->
<meta name="twitter:card" content="summary_large_image">
```
- [ ] Окреме OG-зображення для головних сторінок і статей (за можливості).
- [ ] Перевірити прев'ю в Telegram, Facebook (Sharing Debugger), LinkedIn (Post Inspector).

### 3.2. Іконки
- [ ] `favicon.ico` (32×32) + SVG-фавікон, `apple-touch-icon` 180×180, за потреби `manifest.webmanifest` з іконками 192/512 і `theme-color`.

## 4. Структуровані дані (schema.org, JSON-LD)

Розмітка вставляється як `<script type="application/ld+json">…</script>` і має відповідати видимому вмісту сторінки.

| Тип | Де | Ключові поля |
|---|---|---|
| `Organization` або підтип `LocalBusiness` (`AccountingService`, `Dentist`, `Restaurant`, `Store`…) | на всіх сторінках (у layout) | `name`, `url`, `logo`, `image`, `telephone`, `email`, `address` (`PostalAddress`), `geo`, `openingHoursSpecification`, `areaServed`, `sameAs` (соцмережі), `priceRange` |
| `WebSite` | на всіх сторінках | `name`, `url`, `inLanguage`, `publisher` → `@id` організації |
| `BreadcrumbList` | усі сторінки, крім головної | ланцюжок «Головна → Розділ → Сторінка» з абсолютними URL |
| `Service` | сторінки послуг | `name`, `description`, `provider` → `@id` організації, `areaServed`, за потреби `offers` |
| `Product` + `Offer` | товари | `name`, `image`, `description`, `sku`, `brand`, `offers.price`, `priceCurrency`, `availability` |
| `Article` / `BlogPosting` | статті | `headline`, `image`, `datePublished`, `dateModified`, `author` (`Person` з `name`, за можливості `url`), `publisher` |
| `FAQPage` | блоки «Часті запитання» | `mainEntity` → `Question` / `acceptedAnswer` |

Нюанси:
- Розширені сніпети FAQ Google тепер показує переважно державним і медичним сайтам. Розмітку можна залишати, але на зірочки в пошуку не розраховувати.
- Відгуки й рейтинг (`aggregateRating`) про **власну** компанію на власному сайті до зірочок у пошуку не призводять. Не вигадуйте рейтинг.
- Пов'язуйте сутності через `@id` (`https://домен/#business`), а не дублюйте організацію в кожному блоці.

Перевірка: [Rich Results Test](https://search.google.com/test/rich-results), [Schema Markup Validator](https://validator.schema.org).

## 5. Аналітика, реклама, конверсії

### 5.1. Схема підключення (вибрати одну)
- **Варіант А — `gtag.js` напряму.** Простіше, достатньо для більшості сайтів. Один `gtag.js`, кілька `config`:
  ```js
  gtag('js', new Date());
  gtag('config', 'G-XXXXXXXXXX');     // GA4
  gtag('config', 'AW-XXXXXXXXXX');    // Google Ads — у той самий тег, не другим <script>
  ```
- **Варіант Б — Google Tag Manager**, якщо маркетолог хоче сам керувати тегами. Тоді GA4, Ads і Pixel налаштовуються **всередині GTM**, а сайт лише пушить події в `dataLayer`.
- **Не змішувати:** якщо GA4 є і в GTM, і в `gtag`, кожна подія рахуватиметься двічі.

> Запит до `gtag/js?id=AW-…&cx=c`, який з'являється сам, — це нормальна поведінка Google tag (він підвантажує контейнер для другого призначення), а не дубль у коді. Щоб його прибрати, об'єднайте GA4 і Ads в один тег Google в інтерфейсі Google.

### 5.2. Згода на cookies (Consent Mode v2)
- [ ] Банер із кнопками «Прийняти» / «Лише необхідні» і посиланням на політику конфіденційності; вибір запам'ятовується; є посилання «Налаштування cookies» у футері.
- [ ] Google: **до** будь-яких тегів —
  `gtag('consent','default',{ad_storage:'denied',analytics_storage:'denied',ad_user_data:'denied',ad_personalization:'denied',wait_for_update:500})`,
  після згоди — `gtag('consent','update',{…'granted'})`. Тег Google можна завантажувати одразу: до згоди він надсилає знеособлені сигнали без cookies (для моделювання конверсій).
- [ ] Meta Pixel, Clarity, Hotjar та інші трекери — **лише після** згоди. Відмова → `fbq('consent','revoke')`.
- [ ] Для ЄС/ЄЕЗ Consent Mode v2 обов'язковий для персоналізованої реклами Google. Для інших регіонів — рекомендовано.

> Під час тестування не забувайте про банер: якщо ви натиснули «Лише необхідні», пікселя у вашому браузері не буде, і Pixel Helper покаже, що його «немає».

### 5.3. Стандартні події
Одна функція `track(event, params)` пушить подію в `dataLayer`, `gtag` і `fbq` одночасно.

| Подія GA4 / GTM | Подія Meta | Коли | Параметри |
|---|---|---|---|
| `page_view` | `PageView` | кожна сторінка, **включно з переходами в SPA** | автоматично; для Meta в SPA — вручну при зміні маршруту |
| `generate_lead` | `Lead` | **сервер прийняв заявку** (не клік по кнопці, не помилка валідації, не бот-пастка) | `form_location` |
| `click_call` | `Contact` | клік по `tel:` | `link_location` |
| `click_messenger` | `Contact` | клік по Telegram / WhatsApp / Viber / Messenger | `messenger`, `link_location` |
| `click_email` | `Contact` | клік по `mailto:` | `link_location` |
| `share` | — | кнопки «Поділитися» (не рахувати як контакт) | `method` |
| `purchase` / `begin_checkout` / `add_to_cart` | `Purchase` / `InitiateCheckout` / `AddToCart` | інтернет-магазин | `value`, `currency`, `items` |

- [ ] Кліки ловити **одним** делегованим обробником на `document` (за схемою посилання `tel:`, `mailto:`, `t.me` і т. д.): нові кнопки підхоплюються автоматично.
- [ ] Не передавати персональні дані (ім'я, телефон, пошту) в параметрах подій GA4 і Meta.
- [ ] У GA4 позначити ключові події: Адміністратор → Ключові події (`generate_lead`, за потреби `click_call` тощо).
- [ ] GA4 → Адміністратор → Зберігання даних → **14 місяців**. В Enhanced measurement має бути увімкнено «Зміни історії браузера» (для SPA).

### 5.4. Конверсії Google Ads
- [ ] Створювати як **«Веб-сайт → вручну за допомогою коду»**, а не «перегляд сторінки за URL». Конверсія за переглядом сторінки рахує відкриття сайту, а не звернення. До того ж у поле URL легко вставити домен двічі (`https://домен/https://домен`), і конверсія стане «Неактивною».
- [ ] Одна конверсія на тип дії: «Заявка з форми» (категорія «Надсилання форми для лідів»), «Телефон», «Telegram», «WhatsApp», «Пошта» (категорія «Контакт»). Підрахунок **«Одна»**, цінність — за домовленістю (наприклад, 1 грн).
- [ ] Надсилання — у момент тієї самої дії, що й подія GA4:
  ```js
  gtag('event', 'conversion', { send_to: 'AW-XXXXXXXXXX/МІТКА', value: 1.0, currency: 'UAH' });
  ```
  Фрагмент `gtag_report_conversion(url)` від Google затримує перехід за посиланням. Якщо на сайті вже є власна обробка кліків, достатньо одного виклику вище.
- [ ] Мітки — в налаштуваннях сайту / `.env` (щоб замінити без релізу), з перевіркою формату й витягуванням мітки з повного фрагмента коду.
- [ ] **Без подвійного обліку:** на одну дію — **одна основна** конверсія. Якщо та сама дія імпортується ще й із GA4, імпорт роблять «Додатковим». Старі конверсії за переглядом сторінки — видалити або перевести в «Додаткові».
- [ ] Зв'язати GA4 ↔ Google Ads: Ads → Інструменти → Менеджер даних → Пов'язані продукти → Google Analytics (GA4). Потрібні права «Редактор» у GA4 й «Адміністратор» у Ads. Це може зробити сам власник, доступ розробника не обов'язковий.

### 5.5. Meta Pixel
- [ ] `PageView` на кожній сторінці (і при SPA-переходах), `Lead` для заявки, `Contact` для кліків по контактах.
- [ ] Підтвердити домен у Business Settings.
- [ ] За великого рекламного бюджету — Conversions API (серверне дублювання `Lead` з тим самим `event_id` для дедуплікації).

### 5.6. Джерело заявки (атрибуція)
- [ ] При першому візиті зберегти `utm_*`, `gclid`, `fbclid` (sessionStorage/cookie) і передавати разом із заявкою на сервер. У CRM/адмінці видно, з якої реклами прийшов клієнт.
- [ ] `gclid` дає змогу пізніше завантажувати в Google Ads офлайн-конверсії (наприклад, «заявка стала клієнтом»).
- [ ] Дії поза сайтом (Telegram-бот, дзвінок через колтрекінг, CRM): передати через сайт ключ візиту (наприклад, `t.me/бот?start=<ключ>`), за яким сервер знаходить `client_id`/`session_id` GA4 (cookies `_ga`, `_ga_<ID>`), і надіслати подію через **GA4 Measurement Protocol** з тими самими ідентифікаторами. Тоді подія успадкує рекламне джерело сесії.

### 5.7. Форми
- [ ] Серверна валідація, зрозумілі помилки, введене не стирається при помилці.
- [ ] Захист від спаму без капчі: приховане поле-пастка, мінімальний час заповнення, ліміт заявок з IP. Для спаму **не** надсилати `generate_lead` і конверсію.
- [ ] Чекбокс згоди на обробку персональних даних із посиланням на політику.
- [ ] Сповіщення про заявку (Telegram, пошта, CRM) і збереження в базі, а не лише лист на пошту.

## 7. Контент і структура

- [ ] **Одна сторінка — одна група запитів (інтент).** Сторінки не повинні конкурувати за ті самі запити. Таблиця «сторінка → URL → головний запит → додаткові» зберігається в документації проєкту.
- [ ] Головна → розділи → сторінки послуг/товарів: до будь-якої важливої сторінки не більше 3 кліків.
- [ ] Внутрішня перелінковка: меню, футер, «Інші послуги», «Корисні статті», хлібні крихти. Анкори описові, не «тут» / «детальніше».
- [ ] Сторінка послуги: H1 з запитом, що входить, кому підходить, як працюємо, ціни/від, кейси/відгуки, FAQ, форма заявки.
- [ ] E-E-A-T: сторінка «Про нас», реальні люди й фото, автор у статтях, контакти, реквізити, ліцензії/сертифікати.
- [ ] Блог/новини: окрема сторінка на кожну тему, дата публікації й оновлення, автор, перелінковка на послуги.
- [ ] Унікальні тексти. Не копіювати з інших сайтів, не генерувати масово без редагування.
- [ ] `alt` у всіх змістовних зображеннях (описовий, без спаму ключами), декоративні — `alt=""`.
- [ ] Якщо контент редагується через адмінку: Title/Description/noindex/canonical для сторінок і статей, превʼю сніпета, лічильники довжини.

## 9. Чек-лист запуску

**Перед запуском**
- [ ] Дані з розділу 1 зібрані; немає `TODO` у видимому контенті й розмітці.
- [ ] HTTPS, один канонічний хост, 301 з усіх інших варіантів; DNS не має зайвих записів.
- [ ] Унікальні Title/Description/H1 на всіх сторінках; canonical; OG-зображення.
- [ ] `robots.txt` і `sitemap.xml` відкриваються й коректні; **`noindex` тестового середовища знято**.
- [ ] JSON-LD проходить валідацію без помилок.
- [ ] Банер cookies працює; до згоди трекерів немає (крім Google у режимі «denied»).
- [ ] GA4, Ads, Pixel підключені **по одному разу**; кожна подія й конверсія перевірена в Tag Assistant / Pixel Helper.
- [ ] Тестова заявка: збереглася, прийшло сповіщення, `generate_lead` і конверсія надіслані **один раз**, джерело (utm/gclid) записалося. Тестову заявку видалено.
- [ ] Редиректи зі старого сайту перевірені.
- [ ] PageSpeed (mobile): LCP, CLS, INP у зеленій зоні або близько.

**Після запуску (перший тиждень)**
- [ ] Search Console + Bing: ресурс підтверджено, sitemap додано, запит на індексування ключових сторінок.
- [ ] Google Business Profile: дані збігаються з сайтом.
- [ ] GA4: ключові події позначено, зберігання 14 міс., зв'язок із Google Ads.
- [ ] Google Ads: конверсії мають статус «Записуються конверсії»; немає основних дублів; старі URL-конверсії — додаткові.

**Через місяць**
- [ ] Search Console: помилки індексації, запити, за якими є покази, нові ідеї для сторінок.
- [ ] Порівняти кількість заявок у CRM/адмінці з `generate_lead` у GA4 і конверсіями в Ads. Велика розбіжність означає дублі, ботів або загублені події.

## 10. Типові помилки (з практики)

- Тег GA4/Ads вставлено двічі: у шаблон і через GTM/плагін. Усі події рахуються подвійно.
- Конверсія Ads за «переглядом сторінки» замість дії, або з подвоєним доменом у полі URL. Статус «Неактивно».
- Мітку конверсії переписали вручну з помилкою в регістрі. Конверсія мовчки не рахується.
- `generate_lead` на клік кнопки «Надіслати», а не на успішну відповідь сервера. Рахуються помилки валідації й боти.
- Тестовий `noindex` або `Disallow: /` залишився після запуску.
- AAAA-запис домену веде на старий хостинг. Сертифікат не випускається, частина відвідувачів бачить старий сайт.
- Після зміни DNS «нічого не працює» через TTL: старі записи можуть кешуватися до значення TTL (часто 1–4 години).
- Переливання файлів на сервер разом із локальною базою даних або `.env` затирає продакшен-дані (адмін-акаунти, заявки, налаштування).
- Тестування пікселя після натискання «Лише необхідні» в банері: піксель «не працює», хоча все гаразд.
- Канонічний URL з UTM-мітками або відносний (`/page`) замість абсолютного.
